Folia: make //regen work under regionised threading

//regen builds a detached temporary world (faweregentempworld) and pumps its
chunk task queue while copying generated blocks into the real world. Two Folia
API differences broke it, both traced by running regen on a live server.

1. Level#getCurrentWorldData() is not a getter. Decompiling Folia 26.1.2 shows it
   returns the calling thread's region data and throws on mismatch:

       if (world != this) throw new IllegalStateException("World mismatch: ...");

   Regen wraps the temp world while the thread is ticking the real one, so my
   earlier region-tick read threw "World mismatch: expected faweregentempworld
   but got world" during PaperweightFaweWorldNativeAccess construction, and regen
   failed in 88ms. The same applies to capture-state access in the adapter.
   Both now tolerate a mismatch: an unavailable region tick degrades to 0 (which
   simply means "no tick-boundary flush"), and capture state reads as empty.

2. ServerChunkCache$MainThreadExecutor#pollTask() requires region ownership:

       getCurrentRegionizedWorldData().world == this.world

   The regen world is never ticked by any region, so on a tick thread this threw
   "Polling tasks from non-owned region", and on the global thread NPE'd every
   tick. runTasks now detects both conditions and stops pumping instead of
   letting an exception escape each tick; generation continues via the chunk
   source and the repeating drain task ends cleanly.

Verified on Folia 26.1.2, nine scenarios, zero NPEs and zero watchdog stalls:

    PASS regen:         returned=true in 3736ms
    PASS regen-applied: 5/5 sampled blocks replaced by generated terrain

The regen-applied check marks the region with bedrock first and confirms it is
gone afterwards, so this verifies blocks were written rather than merely that
the call returned true.
